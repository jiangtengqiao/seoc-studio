## 引言

Python 的诞生常被浪漫化为一个人在一个假期里的作品。这个说法大体属实，但假期只是点火时刻，燃料在此前数年的积累里早已备好。本章还原 1989 年 12 月前后 Guido van Rossum 的具体处境与最初的技术决策。

## 为什么是那个假期

1989 年，Guido 三十三岁，在 CWI 的 Amoeba 项目组工作。他多年使用 ABC 的经验告诉他简洁语法的力量，而 Amoeba 的日常又反复提醒他现有工具的不足。圣诞假期办公室安静，项目暂时停摆，他需要一个能让自己在假期里保持状态又有实际价值的消遣，于是决定写一个新语言的解释器。

这个决定有两个值得注意的特征。第一，它是实用主义的。Guido 不是想发明理论，而是想要一个自己明天就能用的工具。第二，它是克制的。最初的目标只是写一个 ABC 的后继者，能跑在 Amoeba 与 Unix 上，能扩展，没有更宏大的计划。

## 名字的来源

Python 这个名字与蛇无关。Guido 是 BBC 喜剧团体 Monty Python 的爱好者，他想要一个简短、独特、带点神秘感的名字，Python 恰好符合。这个名字后来深刻影响了社区文化，官方文档与教程里充斥着 Monty Python 的梗，spam 与 eggs 成为示例变量名的传统正来源于此。

## 最初的技术决策

### 解释执行与字节码

Python 从第一天起就是解释型语言。Guido 选择了先编译为字节码、再由虚拟机执行的架构，这与 ABC 一脉相承，也便于实现交互式解释器。交互式环境让学习者与系统管理员都能立即看到每一行代码的结果，这成为 Python 早期传播的重要助力。

### 一切皆对象

Python 的对象模型在早期就确立了一致性原则，整数、字符串、函数、模块，统统是对象。这个决定当时看来只是美学上的洁癖，后来证明是 Python 元编程能力与框架生态的根基。

### 可扩展的 C 接口

吸取 ABC 封闭的教训，Guido 一开始就把 C 扩展机制做进了语言核心。任何性能敏感或需要操作系统能力的功能，都可以用 C 写成模块挂进解释器。NumPy 在十几年后的爆发，正是踩在这个早期决策的延长线上。

### 缩进语法的坚持

ABC 的缩进语法在当时的主流语言里几乎没有同伴，大括号才是正统。Guido 选择坚持，理由是代码被阅读的次数远多于被编写的次数，缩进强制了视觉结构与逻辑结构的一致。这个决定在当时引来大量嘲笑，后来成为 Python 辨识度最高的特征。

## 1991 年的首次公开发布

假期之后，Guido 继续完善解释器。1991 年 2 月，他把 Python 0.9.0 发布到 alt.sources 新闻组。这个最早的公开版本已经包含了类与继承、异常处理、函数、模块，以及列表、字典等核心数据类型。值得注意的是，函数式风格的 lambda、map、filter 也在很早期出现，虽然 Guido 本人后来对这些特性态度复杂。

早期用户的反馈集中在两个方向，一是要求更多的库，二是要求更好的文档。这两个反馈塑造了 Python 此后几十年的社区文化，内置电池与文档友好成为 Python 区别于同时代语言的重要标签。

## 从个人项目到社区项目

0.9.0 发布后的几年里，Python 的使用者从 CWI 内部扩散到美国国家标准与技术研究院等机构。Guido 1995 年移居美国，Python 的开发重心随之转移。邮件列表取代了新闻组成为主要协作场所，早期贡献者开始提交补丁，Python 从一个人的假期项目逐步变成一个小而活跃的社区项目。

本章的最后需要指出一个常被忽视的事实。Python 早期的增长并不快，它在整个九十年代都活在 Perl 的阴影之下。它的胜利不是爆发式的，而是依靠可读性、教学友好与生态复利，在一个又一个细分领域缓慢替代对手。理解这一点，才能理解 Python 社区为什么如此看重可读性与教学资源。

## 本章要点

- 1989 年圣诞假期是点火时刻，ABC 与 Amoeba 的经验是燃料。
- Python 之名来自 Monty Python，而非蛇，这奠定了社区文化的幽默底色。
- 字节码虚拟机、一切皆对象、C 扩展接口与缩进语法，四项早期决策决定了 Python 此后三十年的走向。
- Python 的增长方式是缓慢渗透，而非爆发替代。
