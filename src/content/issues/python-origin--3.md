## 引言

每一门长寿的语言都有一套可以被复述的设计哲学。Python 的哲学最特别的之处在于，它被写成了诗，藏在解释器里。在任何 Python 环境中输入 `import this`，你会看到 Tim Peters 写下的十九行格言，这就是 Python 之禅。本章逐条解读这些格言的历史语境，并说明它们如何在真实的语言决策中被执行或违背。

## 优美优于丑陋，显式优于隐式

前两条是 Python 美学的总纲。优美不是装饰，而是指解决方案的结构与问题的结构同形。显式则指向一个具体的技术立场，语言不应在你看不见的地方替你做决定。

显式原则的典型执行案例是 self。Python 方法的第一参数必须显式写出 self，不能像某些语言那样隐式存在。初学时这显得啰嗦，但它让实例方法与函数的边界清晰可见，也让描述符协议等高级机制有落点。

## 简单优于复杂，复杂优于繁复

这两条常被连读，分界在于复杂度是否不可避免。面对本质简单的问题，方案必须简单；面对本质复杂的问题，方案可以复杂，但不能繁复，也就是不能引入与问题无关的额外复杂度。

列表推导是这条原则的正面案例。它把遍历加变换这一高频模式压缩为一个表达式，是对本质复杂度的合理封装。反面案例在语言史中也存在，某些特性提案因为引入过多新概念而被拒绝，即使它们能解决真实问题。

## 扁平优于嵌套，稀疏优于稠密

扁平原则直接支持了缩进语法的设计取向，也影响了标准库的组织方式。Python 倾向于宽而浅的模块结构，而非深不见底的继承层级。稀疏原则则关乎代码的呼吸感，一行只做一件事，表达式不过度压缩。

## 可读性很重要

这是十九行里最著名的一句，也是 Python 社区执行最彻底的一条。它的历史背景是 Guido 在 CWI 的经历，研究机构的代码被大量非专业程序员阅读和维护，可读性直接决定代码的存活期。

可读性原则有可操作的推论。命名比注释重要，结构比技巧重要，一致比聪明重要。PEP 8 风格指南的存在与流行，正是这条原则的制度化。

## 特例不足以打破规则，虽然实用性胜过纯粹性

这一对格言承认了哲学的内部张力。Python 不是教条主义语言。最著名的例证是 len 函数。按照一切皆方法调用的纯粹对象取向，长度应该是 `s.len()`，但 Python 选择内置函数 `len(s)`，因为它可读、统一、便于优化。实用性在这里胜过了纯粹性。

## 错误不应静默传递，除非显式静默

这两条塑造了 Python 异常文化的基本面。吞掉异常是 Python 社区最被鄙视的写法之一，裸 except 在代码评审中几乎必然被指出。与此同时，语言提供了显式的例外通道，比如字典的 get 方法、contextlib.suppress，让确实需要静默的场景有正当表达方式。

## 面对歧义，拒绝猜测的诱惑

这一条解释了 Python 的许多不近人情。字符串与字节串不会隐式互转，整数与字符串不能相加，比较不同类型会抛出异常而非给出无意义的结果。语言宁可让程序员多写一行转换，也不愿替程序员猜一个可能错误的答案。

## 应该有一种，最好只有一种，显而易见的方式

这条格言常被引用来批评其他语言的语法冗余，但在 Python 自身的历史里，它更多是一种方向感而非现状描述。格式化字符串就有四种写法，异步模型也经历过多种并存。社区对这条原则的态度是务实的，承认多种方式会在过渡期并存，但长期要收敛。f-string 的普及正是收敛的胜利。

## 命名空间是一个绝妙的主意

最后一条落回工程组织。模块即命名空间，包即命名空间的层级，import 是显式的名字引入。这套机制让大型 Python 项目的依赖关系保持可读，也让标准库可以持续扩张而不污染用户代码。

## 哲学的执行机制

值得强调的是，Python 之禅不是装饰性的宣言，它有执行机制。PEP 流程要求每一项语言变更公开论证，评审者会反复引用这些格言作为论据。一个特性即使技术上可行，如果违背显式原则或可读性原则，也很难通过。哲学由此成为社区治理的工具。

## 本章要点

- Python 之禅的十九条格言可分为美学、错误处理、歧义处理与工程组织四组。
- 实用主义是这套哲学的内置安全阀，纯粹性可以让位于可读与好用。
- 格言通过 PEP 评审进入实际治理，哲学因此不是口号而是制度。
