## 本章目标

读完本章，你将拥有一套可长期使用的 Python 工作环境，理解解释器、编辑器与包管理三者之间的关系，并能独立排查大多数安装问题。

## 安装解释器

Python 解释器是一切的基础。请始终从 python.org 或你的操作系统包管理器获取官方版本，不要从来路不明的整合包安装。

在 Windows 上，安装时务必勾选 Add Python to PATH。这个选项决定你是否能在终端直接输入 `python` 启动解释器。安装完成后打开终端验证：

```
python --version
```

在 macOS 与 Linux 上，系统通常自带一个供系统自身使用的 Python，不要改动它。请安装一份独立的用户级 Python，并用明确的版本命令调用，例如 `python3.12`。

## 编辑器的选择与配置

编辑器不影响程序的正确性，但深刻影响你的学习效率。这里给出两种经过长期验证的配置思路。

第一种是 VS Code。安装后添加 Python 扩展，完成三项设置。其一，在命令面板用 Python Select Interpreter 指向你安装的解释器。其二，打开保存时自动格式化，配合 Ruff 或 Black 作为格式化工具。其三，启用基于语言的错误提示，让拼写错误与类型误用在写代码时就暴露，而不是运行时才暴露。

第二种是轻量组合，任意顺手的编辑器加终端。这条路适合希望理解工具链每个环节的读者。你手动运行 `python script.py`，手动管理虚拟环境，编辑器的职责退化为纯粹的文本编辑。

两条路没有高下之分。本章的建议是，初学者先用 VS Code 把反馈回路缩短，有经验的读者可以回到轻量组合加深理解。

## 虚拟环境是必需品

从第一个正式项目开始，就应当使用虚拟环境。它解决的是依赖隔离问题，让不同项目的第三方库互不干扰。

```
python -m venv .venv
```

创建后激活它。Windows 的 PowerShell 执行 `.venv\Scripts\Activate.ps1`，macOS 与 Linux 执行 `source .venv/bin/activate`。激活成功的标志是终端提示符前出现 `(.venv)` 字样。

此后用 `pip install` 安装的每一个包都只存在于这个环境中。项目结束时删除 `.venv` 目录即可彻底清理，不污染系统。

## 一个最小工作流

把上面的环节串起来，一个标准的日常流程是这样的。进入项目目录，激活虚拟环境，安装依赖，打开编辑器写代码，在终端运行并观察输出，遇到报错先读错误信息的最后一行。

报错信息的最后一行告诉你异常类型与原因，往上追栈帧可以找到出错的具体文件与行号。学会读报错，比记住任何语法都重要。

## 常见问题

问：输入 python 提示找不到命令。答：PATH 未配置，重新安装并勾选对应选项，或使用完整路径调用。

问：pip install 速度很慢。答：网络问题，可配置国内镜像源，但请确认镜像源的可信度。

问：虚拟环境激活脚本报策略错误。答：Windows PowerShell 的执行策略限制，以管理员身份执行一次 `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` 即可。

## 本章要点

- 解释器从官方渠道安装，系统自带 Python 不要动。
- 编辑器的核心价值是缩短写代码与看结果之间的反馈回路。
- 每个项目一个虚拟环境，这是工程习惯的第一课。
