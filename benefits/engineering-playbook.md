# SEOC Studio 工程实践资料包

适用对象：已经具备基础语法能力，准备把练习代码升级为真实项目的学习者。

本资料包提供四类可直接使用的模板。建议复制到自己的项目仓库中，根据项目实际删减，不要为了填写模板而填写模板。

## 一、项目 README 模板

### 项目名称

用一句话说明项目解决什么问题，避免只写技术名词。

### 这个项目解决什么问题

说明使用者在什么场景下遇到困难，以及现有做法为什么不够好。

### 核心功能

- 功能一：说明用户能完成什么动作
- 功能二：说明系统会保存、计算或展示什么结果
- 功能三：说明与同类练习项目相比的差异

### 技术栈

- 语言与运行环境
- 框架与主要依赖
- 数据库或存储方式
- 部署方式

### 本地启动

```bash
# 安装依赖

# 启动开发环境

# 运行测试

```

### 目录结构

```text
project/
├── src/             # 主要源码
├── tests/           # 自动化测试
├── docs/            # 项目文档
└── scripts/         # 辅助脚本
```

### 已知限制

诚实写出目前不支持的功能、性能边界和未处理的异常情况。

### 下一步计划

- 短期：一周内能完成的修正
- 中期：一个月内能完成的结构改进
- 长期：需要更多学习或调研后才能完成的目标

## 三、代码评审清单

### 正确性

- 输入为空、异常或超出边界时是否有明确处理
- 错误信息是否能帮助定位问题
- 异步流程是否处理失败与重复提交
- 权限检查是否在服务端完成

### 可读性

- 函数是否只做一件清楚的事
- 命名是否表达业务含义
- 复杂分支是否有足够的拆分
- 注释是否解释原因，而不是复述代码

### 可维护性

- 配置是否与代码分离
- 模块之间是否有清楚边界
- 新增功能是否需要修改过多无关文件
- 是否存在重复逻辑可以抽出

### 安全与隐私

- 密钥是否没有写入代码
- 用户输入是否经过校验
- 敏感数据是否避免写入日志
- 权限与数据访问是否符合最小授权原则

### 测试

- 关键路径是否有自动化测试
- 错误路径是否有测试
- 测试是否能独立重复运行
- 本次修改是否破坏了既有测试

## 四、发布检查表

### 发布前

- 所有测试通过
- 构建产物可以正常生成
- 环境变量已在目标环境配置
- 数据库迁移脚本已备份并可执行
- 回滚方式已经明确

### 发布中

- 记录发布时间
- 记录发布版本
- 保留可回退的上一版本
- 观察错误日志与关键指标

### 发布后

- 验证首页与核心流程
- 验证登录、支付、写入等关键动作
- 检查新增错误日志
- 记录本次发布遗留问题

## 使用建议

每个项目至少保留 README、调试日志和发布检查表。代码评审清单可以在每次合并前使用，复盘模板建议每月或每季度使用一次。模板的价值不在形式，而在让问题、决策和进度留下可追踪的记录。
